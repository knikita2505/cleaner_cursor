# План тестирования для ИИ-агента

## Цель
Этот документ предназначен для ИИ-агента, который должен проверить написанный код на соответствие требованиям, Apple Guidelines и best practices. Агент должен пройти по каждому пункту и провести code review.

---

## 1. Компиляция и базовая работоспособность

### Чек-лист
- [ ] Проект компилируется без ошибок (Product → Build)
- [ ] Проект компилируется без warnings (кроме deprecation от SDK)
- [ ] Все SPM-зависимости разрешаются
- [ ] Приложение запускается на симуляторе без crash
- [ ] Приложение запускается на реальном устройстве

### Что проверить в коде
```
1. Все import-ы существуют и не дублируются
2. Нет неиспользуемых переменных и функций
3. Нет force-unwrap (!) в production-коде (допускается только в тестах и preview)
4. Все @Published свойства используются в UI
5. Нет retain cycles (weak self в closures)
```

## 2. Архитектура и структура

### Чек-лист
- [ ] Структура директорий соответствует спецификации (Core/, Features/, UI/)
- [ ] Каждая Feature имеет Views/ и (опционально) ViewModels/
- [ ] Сервисы — синглтоны с `static let shared`
- [ ] ViewModels — `@MainActor class ViewModel: ObservableObject`
- [ ] Нет бизнес-логики во View (только привязка к ViewModel)
- [ ] Нет UI-кода в сервисах

### Правила code review
```
1. View содержит ТОЛЬКО: body, @State, @Binding, @EnvironmentObject, вспомогательные computed properties
2. ViewModel содержит: бизнес-логику, @Published, методы трансформации данных
3. Service содержит: работу с API/SDK/FileSystem, модели данных
4. Theme содержит: ТОЛЬКО константы (цвета, шрифты, отступы)
5. Extensions содержит: ТОЛЬКО расширения стандартных типов
```

## 4. PhotoService (Очистка фото)

### Чек-лист
- [ ] Запрос разрешения на доступ к фото работает
- [ ] Обработка отказа (показ модалки с кнопкой Settings)
- [ ] Сканирование дубликатов находит реальные дубликаты
- [ ] Сканирование похожих фото работает
- [ ] Скриншоты корректно фильтруются
- [ ] Live Photos корректно фильтруются
- [ ] Burst Photos корректно группируются
- [ ] Кэш сохраняется и загружается
- [ ] Кэш инвалидируется при изменении библиотеки
- [ ] Удаление вызывает системный диалог iOS
- [ ] После удаления — счётчики обновляются
- [ ] UI не блокируется при сканировании большой библиотеки
- [ ] Thumbnails загружаются и отображаются

### Тесты
```
1. Пустая библиотека → все счётчики = 0, нет crash
2. Библиотека с 1 фото → сканирование, 0 дубликатов
3. Библиотека с дубликатами → находит группы
4. Повторное сканирование → берёт из кэша (быстро)
5. Удаление фото → запись в CleaningHistory
6. Удаление > 50 фото (free) → показ paywall
```

## 12. Инструкция для ИИ-агента

### Как проводить code review
```
1. Прочитать каждый Swift файл
2. Проверить соответствие архитектуре MVVM
3. Проверить отсутствие force-unwrap (!)
4. Проверить обработку ошибок (try/catch, guard, if let)
5. Проверить @MainActor на классах с @Published
6. Проверить weak self в escaping closures
7. Проверить использование дизайн-системы (AppColors, AppFonts, AppSpacing)
8. Проверить отсутствие хардкод строк (должны быть константы)
9. Проверить наличие документации на публичных API
10. Составить список найденных проблем с приоритетами (critical/high/medium/low)
```

### Приоритеты проблем
- **Critical:** crash, утечка данных, неработающая функция
- **High:** нарушение архитектуры, отсутствие обработки ошибок
- **Medium:** нарушение дизайн-системы, отсутствие анимаций
- **Low:** стиль кода, именование, комментарии
